# Contributing

Thank you for your interest in contributing to the Terraform provider for Microsoft Exchange.

## How to Contribute

### Reporting Bugs
Open an issue using the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md).

### Requesting a New Resource
Open an issue using the [new resource template](.github/ISSUE_TEMPLATE/new_resource.md).

### Submitting Code

1. Fork the repository
2. Create a feature branch: `git checkout -b feat/msexchangeonline_my_resource`
3. Make your changes
4. Run tests: `make test`
5. Format code: `make fmt`
6. Regenerate the documentation: `make docs` (never edit `docs/` by hand)
7. Submit a pull request

## Development Setup

### Requirements
- Go 1.25+ (see `go.mod`)
- PowerShell 7+ (`pwsh`)
- ExchangeOnlineManagement PowerShell module
- A Microsoft 365 developer tenant (for acceptance tests)

### Local Installation
```bash
git clone https://github.com/workplace-as-code/terraform-provider-msexchangeonline
cd terraform-provider-msexchangeonline
make install
```

## Adding a New Resource

1. Create `internal/resources/my_resource.go`
2. Create `bridge/scripts/my_resource.ps1` (embedded automatically at build time)
3. Register it in `internal/resources/registry.go`, with the `Get-` cmdlet noun that lists its objects (`terraform query`)
4. Add the example `examples/resources/msexchangeonline_my_resource/resource.tf` (no `terraform` or `provider` block) and the import examples `import.sh`, `import-by-string-id.tf` and `import-by-identity.tf` next to it
5. Add the page template `templates/resources/my_resource.md.tmpl` (copy an existing one: it sets the menu category, the permissions and the Microsoft documentation links), then run `make docs` and `make examples`

### Documentation

`docs/` is generated by [tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs) from the provider schema (attribute descriptions live in the Go code), `templates/` and `examples/`: run `make docs` after changing any of them. CI fails when `docs/` is out of date. Guides are written in `templates/guides/` and copied as is.

### Bridge script contract

Every script must follow the same output contract, otherwise Terraform state can be lost:

- Success: one JSON object on stdout, exit code 0.
- `Get` on an object that does not exist: empty stdout, exit code 0. This is the only case where the provider removes a resource from state.
- Any other failure (authentication, throttling, invalid input): message on stderr, non-zero exit code. Never swallow errors with `-ErrorAction SilentlyContinue` on write operations.

Scripts normally run inside a long-lived PowerShell process (`bridge/scripts/bridge_host.ps1`) that serves many requests and keeps the Exchange connection opened by `auth.ps1`. Each script runs in its own scope, so plain variables are safe. Never store state in `$global:` variables or rely on anything left over from a previous request. Write results with `Write-Output` and errors with `[Console]::Error.WriteLine` or `throw`: the host captures both per request. Set `EXCHANGE_BRIDGE_MODE=oneshot` to run each script in its own process while debugging.

Secrets reach `auth.ps1` through environment variables, never through parameters. To test a script change without rebuilding the provider, point `EXCHANGE_BRIDGE_DIR` at your local `bridge/scripts` folder.

## Commit Convention

We use [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add msexchangeonline_owa_mailbox_policy resource
fix: handle missing transport rule gracefully
docs: update authentication guide
chore: bump terraform-plugin-framework to 1.6.0
```

## Code of Conduct

Be respectful. We're all here to build something useful together.
