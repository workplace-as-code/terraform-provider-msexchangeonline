# msexchangeonline_management_role (Resource)

Manages a custom management role (`New-ManagementRole -Parent`): a copy of a built-in role that keeps only some of its cmdlets, and optionally only some of their parameters. Assign it with `msexchangeonline_management_role_assignment`.

## Example Usage

```terraform
# Read recipients and change their phone numbers, nothing else
resource "msexchangeonline_management_role" "helpdesk_phone" {
  name        = "Helpdesk Phone"
  parent      = "Mail Recipients"
  description = "First-level support: phone numbers only"

  cmdlets = ["Get-Mailbox", "Get-Recipient", "Get-User", "Set-User"]
  cmdlet_parameters = {
    "Set-User" = ["Identity", "Phone", "MobilePhone"]
  }
}
```

## Schema

### Required

- `cmdlets` (Set of String) Cmdlets the role keeps from its parent, for example `Get-Mailbox`. A role can only keep cmdlets of its parent: it never grants more.
- `name` (String) Name of the role. Changing it creates a new role.
- `parent` (String) Role the custom role is copied from, for example `Mail Recipients`: a built-in role or another custom role. Changing it creates a new role.

### Optional

- `cmdlet_parameters` (Map of Set of String) Parameters kept for some cmdlets, by cmdlet, for example `{ "Set-User" = ["Identity", "Phone"] }`. Include the parameters the cmdlet needs to run, such as `Identity`. The cmdlets of `cmdlets` that are not in the map keep all the parameters of the parent.
- `description` (String) Description of the role.

### Read-Only

- `id` (String) The role name.

## Limitations

A custom role can only remove rights from its parent: `cmdlets` and `cmdlet_parameters` can only name
cmdlets and parameters of the parent role. Built-in roles cannot be managed or imported. A role that is
still assigned cannot be deleted: refer to it from `msexchangeonline_management_role_assignment` by
`msexchangeonline_management_role.<name>.name`, so that Terraform removes the assignments first.

## Permissions

The provider's app registration needs the **Role Management** Exchange management role, which lets it grant itself any other role: give it only to the pipeline that manages the Exchange delegation. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeonline/blob/main/tools/new_role_group.ps1) includes it with `-IncludeRoleManagement`. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/authentication).

## Import

Import using the role name:

```terraform
import {
  to = msexchangeonline_management_role.helpdesk_phone
  id = "Helpdesk Phone"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeonline_management_role.helpdesk_phone
  identity = { id = "Helpdesk Phone" }
}
```

Or with the CLI:

```shell
terraform import msexchangeonline_management_role.helpdesk_phone "Helpdesk Phone"
```

To import every existing object at once, see [Import an existing tenant](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/import_existing).
