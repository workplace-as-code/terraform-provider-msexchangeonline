# msexchangeonline_service_principal (Resource)

Registers a Microsoft Entra application in Exchange Online (`New-ServicePrincipal`), so that `msexchangeonline_management_role_assignment` can give it roles limited to a scope: RBAC for Applications. The app registration itself, and its consent, are managed in Microsoft Entra.

## Example Usage

```terraform
# Register an app of Microsoft Entra in Exchange Online, to give it scoped roles
resource "msexchangeonline_service_principal" "mail_sender" {
  app_id       = "00000000-0000-0000-0000-000000000000"
  object_id    = "11111111-1111-1111-1111-111111111111"
  display_name = "Mail sender"
}
```

## Schema

### Required

- `app_id` (String) Application (client) ID of the app registration. Changing it creates a new service principal.
- `object_id` (String) Object ID of the app's enterprise application (service principal) in Microsoft Entra, not the object ID of the app registration. Changing it creates a new service principal.

### Optional

- `display_name` (String) Name shown in Exchange Online.

### Read-Only

- `id` (String) The app ID.

## RBAC for Applications

RBAC for Applications limits what an application can reach in Exchange Online, with the scopes of
`msexchangeonline_management_scope`. It replaces application access policies. The app registration and its
enterprise application are created in Microsoft Entra; this provider registers the app in Exchange
and gives it its roles:

```terraform
resource "msexchangeonline_service_principal" "mail_sender" {
  app_id    = azuread_application.mail_sender.client_id
  object_id = azuread_service_principal.mail_sender.object_id
}

resource "msexchangeonline_management_role_assignment" "mail_sender" {
  role                  = "Application Mail.Send"
  app                   = msexchangeonline_service_principal.mail_sender.app_id
  custom_resource_scope = msexchangeonline_management_scope.france.name
}
```

A Microsoft Graph permission granted to the app in Microsoft Entra, such as `Mail.Send`, applies to every
mailbox on top of the scoped role: do not grant it, or the scope no longer limits anything. The provider
cannot check it.

## Permissions

The provider's app registration needs the **Role Management** Exchange management role, which lets it grant itself any other role: give it only to the pipeline that manages the Exchange delegation. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeonline/blob/main/tools/new_role_group.ps1) includes it with `-IncludeRoleManagement`. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/authentication).

## Import

Import using the app ID:

```terraform
import {
  to = msexchangeonline_service_principal.app
  id = "00000000-0000-0000-0000-000000000000"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeonline_service_principal.app
  identity = { id = "00000000-0000-0000-0000-000000000000" }
}
```

Or with the CLI:

```shell
terraform import msexchangeonline_service_principal.app "00000000-0000-0000-0000-000000000000"
```

To import every existing object at once, see [Import an existing tenant](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/import_existing).
