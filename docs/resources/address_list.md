# msexchangeonline_address_list (Resource)

Manages an address list: the recipients that match a filter, shown to users through an address book policy (`New-AddressList`). Attributes left out of the configuration take the Exchange default when the object is created and are not managed afterwards. In Exchange Online, users only see an address list through an address book policy. Exchange Online cannot recalculate the members of a list: after a change of `recipient_filter`, a recipient enters or leaves the list when its own object next changes. Precanned filters (`-IncludedRecipients` and `-Conditional*`) are not managed: an imported precanned list shows the equivalent filter in `recipient_filter`, and applying writes it as a custom filter.

## Example Usage

```terraform
# The sales team of the Contoso entity, set in CustomAttribute1 and Department.
resource "msexchangeonline_address_list" "sales" {
  name             = "Contoso - Sales"
  recipient_filter = "CustomAttribute1 -eq 'Contoso' -and Department -eq 'Sales'"
}

# A list nested under the sales list.
resource "msexchangeonline_address_list" "sales_paris" {
  name             = "Contoso - Sales - Paris"
  container        = msexchangeonline_address_list.sales.name
  recipient_filter = "CustomAttribute1 -eq 'Contoso' -and City -eq 'Paris'"
}
```

## Recipient filter

Exchange rewrites the filter: `CustomAttribute1 -eq 'Contoso' -and Department -eq 'Sales'` comes back as `((CustomAttribute1 -eq 'Contoso') -and (Department -eq 'Sales'))`. The state keeps the configured text as long as Exchange returns the text it wrote, and shows Exchange's text when the filter was changed outside Terraform. After an import, the state holds Exchange's text: with a configuration written by hand, the first apply writes the same filter again in the configured form.

## Schema

### Required

- `name` (String) The name. Changing it creates a new object.

### Optional

- `container` (String) Name of the parent address list, for a list nested in another one. Empty for a top-level list. Changing it creates a new list.
- `display_name` (String) The name shown in Outlook. Defaults to `name`.
- `recipient_filter` (String) OPATH filter of the recipients in the list, for example `Company -eq 'Contoso' -and RecipientType -eq 'UserMailbox'`. Exchange rewrites it with parentheses: the configured text is kept as long as Exchange returns the text it wrote.

### Read-Only

- `id` (String) The object name (same as `name`).

## Permissions

The provider's app registration needs the address list cmdlets of the **Address Lists** Exchange management role, which the role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeonline/blob/main/tools/new_role_group.ps1) includes. Exchange Online does not give this role to Organization Management by default. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/authentication).

## Import

Import using the list name:

```terraform
import {
  to = msexchangeonline_address_list.sales
  id = "Contoso - Sales"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeonline_address_list.sales
  identity = { id = "Contoso - Sales" }
}
```

Or with the CLI:

```shell
terraform import msexchangeonline_address_list.sales "Contoso - Sales"
```

To import every existing object at once, see [Import an existing tenant](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/import_existing).
