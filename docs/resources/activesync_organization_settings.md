# msexchangeonline_activesync_organization_settings (Resource)

Manages the Exchange ActiveSync settings of the organization: what happens to mobile devices that match no device access rule (`Set-ActiveSyncOrganizationSettings`). This is a singleton: there is exactly one per tenant. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange.

## Example Usage

```terraform
# Devices that match no device access rule wait in quarantine.
resource "msexchangeonline_activesync_organization_settings" "this" {
  default_access_level  = "Quarantine"
  admin_mail_recipients = ["mobility@contoso.com"]
  user_mail_insert      = "Your device is waiting for approval by the mobility team."
}
```

## Schema

### Optional

- `admin_mail_recipients` (List of String) Email addresses notified when a device is quarantined.
- `allow_access_for_unsupported_platform` (Boolean) Let devices that do not support ActiveSync policies connect.
- `default_access_level` (String) Access of the devices that match no `msexchangeonline_activesync_device_access_rule`. Valid values: `Allow`, `Block`, `Quarantine` (case-insensitive).
- `user_mail_insert` (String) Text added to the message sent to users whose device is quarantined, up to 256 characters.

### Read-Only

- `id` (String) Always `default`.

## Permissions

The provider's app registration needs the ActiveSync cmdlets of the **Organization Client Access** Exchange management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeonline/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only these cmdlets: the built-in role can also change the protocols of each mailbox and trust partner applications. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/authentication).

## Import

The resource is a singleton. Import it with the ID `default`:

```terraform
import {
  to = msexchangeonline_activesync_organization_settings.this
  id = "default"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeonline_activesync_organization_settings.this
  identity = { id = "default" }
}
```

Or with the CLI:

```shell
terraform import msexchangeonline_activesync_organization_settings.this "default"
```

To import every existing object at once, see [Import an existing tenant](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/import_existing).
