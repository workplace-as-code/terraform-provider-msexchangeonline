# msexchangeonline_management_role_assignment (Resource)

Manages a management role assignment (`New-ManagementRoleAssignment`): gives a role to a role group or to an application, optionally limited to the recipients of a scope. The scopes are authoritative: a scope added outside Terraform shows as a change.

## Example Usage

```terraform
# The help desk of the French subsidiary changes the phone numbers of its users.
# Refer to the role, role group and scope resources, for example
# msexchangeonline_management_role.helpdesk_phone.name, so that Terraform creates
# them first and deletes the assignment before them.
resource "msexchangeonline_management_role_assignment" "helpdesk" {
  role                         = "Helpdesk Phone"
  role_group                   = "Helpdesk France"
  custom_recipient_write_scope = "France"
}
```

## Schema

### Required

- `role` (String) The management role: a built-in role, a `msexchangeonline_management_role`, or for an application an `Application *` role such as `Application Mail.Read`. Changing it creates a new assignment.

### Optional

- `app` (String) Application (client) ID of the `msexchangeonline_service_principal` that gets the role (RBAC for Applications). Changing it creates a new assignment.
- `custom_recipient_write_scope` (String) Management scope (`msexchangeonline_management_scope`) that limits the recipients the role can change.
- `custom_resource_scope` (String) Management scope that limits the mailboxes an application can reach. Only with `app`.
- `enabled` (Boolean) Whether the assignment applies. A new assignment is enabled unless this is `false`.
- `exclusive_recipient_write_scope` (String) Exclusive management scope that limits the recipients the role can change.
- `name` (String) Name of the assignment. Exchange names it `<role>-<role group or app>` when it is not set. Changing it creates a new assignment.
- `recipient_administrative_unit_scope` (String) Microsoft Entra administrative unit, by ID, that limits the recipients the role can change.
- `recipient_group_scope` (String) Group whose members are the only recipients the role can change.
- `recipient_relative_write_scope` (String) Built-in recipient scope, for example `Organization` or `MyGAL`, when no other scope is set. Exchange sets it to the type of the scope otherwise.
- `role_group` (String) Name of the role group that gets the role. Changing it creates a new assignment.

### Read-Only

- `id` (String) The assignment name.

## Scopes

Set at most one write scope. Without one, the role applies to the recipients of its built-in scope,
`recipient_relative_write_scope` (the whole organization by default). The scopes are authoritative: removing
a scope from the configuration gives the role back its built-in scope.

Assignments to role assignment policies are not managed by this resource.
Role assignments to users are not managed.

## Permissions

The provider's app registration needs the **Role Management** Exchange management role, which lets it grant itself any other role: give it only to the pipeline that manages the Exchange delegation. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeonline/blob/main/tools/new_role_group.ps1) includes it with `-IncludeRoleManagement`. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeonline/latest/docs/guides/authentication).

## Import

Import using the assignment name:

```terraform
import {
  to = msexchangeonline_management_role_assignment.helpdesk
  id = "Helpdesk Phone-Helpdesk"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeonline_management_role_assignment.helpdesk
  identity = { id = "Helpdesk Phone-Helpdesk" }
}
```

Or with the CLI:

```shell
terraform import msexchangeonline_management_role_assignment.helpdesk "Helpdesk Phone-Helpdesk"
```
